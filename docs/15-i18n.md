# Khmer and English

Every screen works in English and Khmer. Phnom Penh students and officers are the main users, and a Khmer screen is what makes the app theirs. Priority P1. Estimate 2 hours, plus a native reader's review.

## Rules

- UI strings live in `web/i18n.js` as two tables, `en` and `km`, with the same keys. `t(key, vars)` escapes each `{var}`. A missing Khmer key falls back to English.
- Catalog words (labels, definitions, keywords, aliases, caveats) are `L10n` pairs in `catalog.json`.
- Verdict headlines and templates are keyed by verdict key and language on the server (`docs/13-explainer.md`).
- Numbers keep ASCII digits in both languages, so the explainer check stays simple. Readers accept Khmer digits (០–៩) and convert them.
- The font stack is Geist for Latin and Noto Sans Khmer for Khmer, both vendored. The page sets `lang="km"` when Khmer is on.
- A language button in the header switches the language. The browser remembers it in `localStorage`.

## Acceptance

- A test confirms that `en` and `km` have the same keys and the same placeholders in each string.
- A test confirms that every `t("...")` key in `app.js` exists in `en`, and that no key goes unused.
- The five demo sentences, translated, give the same `Question` through the Khmer keyword reader.

## Known gap

The prototype's Khmer was drafted by AI and never reviewed by a native reader. That covers about 55 claim-desk strings, the catalog words, and the Khmer keyword lists. Book 30 minutes with a native Khmer reader before the pitch. Until then, the footer says that the Khmer is a draft.
